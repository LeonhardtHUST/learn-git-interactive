# 第 5 章 分布式工作流（明确说明 / 暂未提供交互实验）

本章对应《Pro Git》第二版第 5 章，讨论团队如何在「每个人都能完整克隆」的模型下组织协作。

## 关键概念

- **集中式工作流**：所有人向同一个中央仓库的同一分支推送，最简单，适合小团队。
- **集成管理者工作流**：每个开发者拥有自己的公开仓库，维护者「拉取」贡献并合并。GitHub 的 Pull Request 即其变体。
- **独裁者与副官工作流**：Dictator 决定哪些被合并，Lieutenants 分管不同子系统，适合超大型项目（如 Linux 内核）。
- **良好贡献的约定**：基于主线切出主题分支、保持提交小而聚焦、`rebase` 让自己的提交基于最新主线、写好提交信息。

## 本路线覆盖情况

- 分支、合并、冲突、变基、推送、拉取等「机制」已在 `ch03-branch` 全部以真实仓库演练。
- 本章聚焦「如何用这些机制组织团队流程」，属于方法论，以说明为主。
